# Canvas Notes

A notes app where every page is a free canvas. Put text, images, audio, PDFs, checklists, code and tables anywhere, group pages, tag them, and browse them as cards with live thumbnails.

It runs on your laptop (Linux, also Windows and macOS) and on Android. The two keep the same notes by syncing directly over your Wi-Fi. There's no account, no server and no internet involved. Pages live in a SQLite database and images are plain files next to it.

## Features

- **Closing the sidebars.** The library's **sidebar** has a button at the top right of its header (**Hide sidebar**), and **Ctrl+\\** hides or shows it from anywhere in the library; a small button at the top left brings it back, and the page uses the room. On the **Cards** screen the **folders** panel has its own **Hide folders** button (**Ctrl+Shift+\\**), with **Show folders** beside the breadcrumb. Each is remembered on this device. On a phone-sized screen the navigation bar always stays. **?** lists every shortcut, in the library as on a page.
- **Moving around a big page.** A small **map** in the corner appears whenever part of the page is out of view: click or drag on it to go there (**M** hides it). The **zoom %** button opens a menu: zoom to fit, zoom to the selection (Shift+2), 50 / 100 / 200%, and the map switch. Deleting boxes shows a toast with **Undo**.
- **Free canvas.** Drag a box by the **Move** handle in its bar, or by grabbing just outside or inside its edge (the cursor turns into a move cursor). Resize from the corner, overlap them, and send them to the back. A new page is a sheet with edges (see *Finite pages* below). On an **infinite** page (Page size → Infinite) there are no edges: scroll or pan in any direction and more canvas opens up, so you can place boxes above and to the left of where you started as well as below and to the right. **Ctrl + 1** zooms to fit everything on the page, which is handy when you've wandered far. Pinch to zoom on phones.
- **Reordering list items.** Hover a checklist item and drag the ⠿ handle on its left to move it; a blue line shows where it will land. With the cursor in an item, **Alt + ↑ / ↓** moves it too. One move is one undo step.
- **Multi-select.** Drag across empty space or Shift-click to select several boxes, then move, duplicate or delete them together.
- **Undo and redo** for everything on the canvas (Ctrl+Z, Ctrl+Shift+Z, or the header buttons). Typing in one box counts as a single step.
- **Rich text** (TipTap): headings, bold/italic/underline/strike, lists, quotes, inline code and links. Formatting is kept when you paste from other apps.
- **Images** can be pasted, dropped or picked from a file. Originals are kept, except files over 4096 px, which are scaled down.
- **Groups and subgroups.** Groups can hold subgroups, as many levels deep as you like. **Groups** in the sidebar opens a page of group cards (name, colour, page and subgroup counts) with a **Search groups** box that also finds subgroups, by name or by where they sit (e.g. "work ml"). **New group** is at the top of that page.
  - Opening a group shows its subgroups as cards, then its pages plus everything in its subgroups. The title and the links above it show where you are, e.g. "Groups / Work / ML projects"; click any of them to go back up.
  - In a group card's **⋯** menu: **New subgroup…**, **Move into** another group (or back to the top level), rename, colour and delete. On the laptop you can also drag a page card or a group card onto a group card to move it in. The sidebar's **Ungrouped** entry is also a drop target for pages.
  - **Browse groups** and **Browse tags** are in the command palette (Ctrl+P).
  - Deleting a group never deletes its contents. Its pages and subgroups move up a level.
  - A new subgroup takes its parent's colour, which you can change.
- **Desktop widgets (laptop app).** Pin a box or a whole page to your desktop, like Windows Sticky Notes. Use the pin button in a box's bar, **Pin to desktop** in a page card's menu, **Pin this page to the desktop** in the command palette (Ctrl+P), or select several boxes and choose **Pin to desktop** in the bar at the bottom (one widget each).
  - A widget is a small borderless window with a title strip you drag. What's in it is live and editable: type, tick items, and the change is saved to the same page and appears in the main window (and syncs). Edits made elsewhere show up within a few seconds.
  - The strip's buttons: keep it on the desktop (behind other windows) or float it above them, open the page in Canvas Notes, and remove it from the desktop. Position and size are remembered.
  - **Settings → Desktop → Show my widgets when I log in** starts Canvas Notes at login, hidden in the system tray, so the widgets are there as soon as you open the laptop. Closing the main window keeps the app running in the tray (and while any widget is open); **Quit** in the tray menu stops it.
  - If a pinned box or page is deleted, its widget says so and can be removed. On some Linux desktops (Wayland) a window can't be kept behind others: use the float-above setting there.
  - Widgets live in `src/widgets/` (what is pinned, remembered in the settings table) and `src-tauri/src/widgets.rs` (the windows and the tray). A widget window may only read and write the app's own data; it cannot open dialogs, create windows or change start-at-login (`capabilities/widget.json`).
- **Search with filters.** The search box on All pages finds pages whose title, tags or text contain every word you type, in any order (put "quotes" around words that must stay together). Add operators to narrow it: `#travel` or `tag:travel` (exact tag), `has:image` (a box of that kind: text, image, audio, pdf, checklist, code, table, frame, sticky, or drawing), `in:work` (pages in a group whose name contains that, subgroups included), and `after:2026-01-01` / `before:2026-02-01` (last edited on or after / up to the end of that day). They combine: `#plan has:checklist after:2026-03-01 budget`. An operator with a value it can't use (an unknown kind, a date that doesn't exist) is ignored instead of hiding every page. Words used to match the whole phrase; they now match separately.
- **Cards.** **Cards** in the sidebar opens your cards: each card shows a cover picture and a label (a card with no picture shows the first letter of its label). Click a card to open it: a large picture, the label and a rich-text details box, all editable right there. **Add picture** / **Change picture** / **Remove** manage the cover (with the AI assistant add-on on, **Generate with AI** sits beside them: see Add-ons below); **Delete** sends it to Trash. A card is not a page: it has no canvas of its own and can't be opened as one (an old address that points at a card goes to the Cards screen).
  - **Folders and sections.** Cards have a filing system of their own, separate from the groups that hold pages. On the left of the Cards screen is a tree: **All cards**, then your **folders**, and inside a folder its **sections**, which can have sections of their own, as deep as you like (**Plants** › **Indoor** › **Ferns**). Open a folder and its sections are laid out like **frames**, one after another down the page: each section has a coloured **heading** on top (its name, how many cards it holds, a **+** to add a card to it and a **⋯** menu), its **cards** are shown right below, then the sections inside it (each the same, one level in), and when those are finished the **next section** follows. The heading of the top-level section you are in stays at the top while you scroll through its cards. The chevron rolls a section up so its cards (and sections) are hidden, and it stays rolled up next time. Click a section's name to open just that section, with a breadcrumb (**Cards / Plants / Indoor**) you can click to go back up; at the top level the cards that are not in a folder come first and the folders follow as sections. **New folder** (at the top level) / **New section** (inside one) makes one; each has a **⋯** menu to add a section, rename, change its colour, **Move up / Move down** among its neighbours (sections are shown in the order you made or arranged them), move it into another place (never into itself) or delete it. Deleting one never deletes cards: its cards and sections move up a place. Drag a card onto a folder or section (in the tree, anywhere on a section, or the breadcrumb) to file it there, and drag a section's heading onto another to move it with everything inside; without a mouse, open the card and use its **Folder** picker. The numbers beside each folder count the cards in it and in its sections. **New card** creates the card in the place you are looking at. Search looks through everything inside where you are, however deep. **Names and descriptions.** Every folder and section can be edited in place: the pencil in its heading (or **Edit name and description…** in its **⋯** menu, or click its description) opens a small form for its **name** and a **description**, a few lines about what it is for. Enter saves the name, Ctrl+Enter the description, Esc cancels; an empty name is not accepted, and emptying the description removes it. The description shows under the heading (and under the title when you open that section), keeps its line breaks, and is saved, synced and backed up with the section. Folders and sections are saved, synced and backed up like everything else, and never appear among your page groups. (Cards that were filed under page groups before this existed show as not in a folder, with a button at the top to **Bring them into card folders**: it makes matching folders and sections; your page groups are left as they are.)
  - **Tags.** Open a card to give it **tags** (type one and press Enter or comma; tags other cards use are suggested). Tag chips above the cards (with counts for what is shown) filter by tag; click again to clear. In the search box, `#garden` or `tag:garden` matches that exact tag and can be combined with words and other tags (`#travel hotel`).
  - **New card** is in the Cards header and the command palette (Ctrl+P, also **Browse cards**). The Cards screen has its own search (label, details and tags) and sort (label, last edited, newest).
  - **Cards on a page.** The **Card** button in a page's toolbar (beside Text, Image and the rest) puts a card on the page like any other box: **New card** makes a card and opens it at once to give it a picture and a label, and **Add an existing card** lists the 12 most recently edited cards. The box shows the card's picture and label. Tap it (without dragging) to open its details, or use **Open** on its hover bar; drag it to move it. The card itself stays in Cards: the box only points at it, so deleting the box leaves the card, the same card can sit on several pages, and a card deleted from Cards leaves a "This card was deleted" box to remove. Markdown export writes the card's label and details as a quote; page thumbnails and PNG/PDF export show its picture and label. `has:card` finds pages that have one. An older app version doesn't know these boxes: update both devices together.
  - Cards are kept apart from pages: they don't appear in All pages, Groups, Tags, search counts or the link graph. Underneath, a card is a page of its own kind (`kind = 'card'`), so it is saved, synced, backed up and trashed like one. An older app version shows a card as an ordinary page, so update both devices together.
- **Library:**
  - Cards show a real miniature of each page.
  - Groups get coloured tabs.
  - Tags work as filters. **Tags** in the sidebar opens a page of every tag with its page count, a **Search tags** box and a sort (name or most pages); open a tag to see its pages.
  - Search covers everything written on the pages.
  - On the laptop, you can drag a page card onto a group card on the Groups page.
  - A deleted page can be restored from the "Undo" toast.
- **Trash.** Deleted pages go to **Trash** in the sidebar, where you can **Restore** them or **Delete forever**. After 30 days (or the 7 or 90 you choose in Settings) a trashed page's content is removed automatically. The deletion itself still syncs to your other devices, and so does **Delete forever**, so a page you removed for good can't be restored from another device.
- **History.** The **History** button in a page's header lists earlier versions of the page with a miniature of each. **Restore this version** puts back its boxes and arrows (the title, tags and group stay), and Ctrl+Z undoes it. A version is saved at most once an hour while you edit, and also before a sync replaces your copy with another device's. Hourly versions are kept for 2 days, then one per day for 30 days. History stays on the device where you made it and is never synced.
- **Snap guides.** While you drag or resize, a box's edges and centre snap to other boxes' edges and centres, and a pink line shows the match. Hold Alt to move freely.
- **Connector arrows.** Hover a box to show four connection dots; drag from a dot onto another box to draw an arrow between them (dropping on empty space cancels). Arrows always take the shortest side-to-side route and stay attached as either box moves or resizes. Click an arrow to select it, then use its menu to set a label, choose arrowheads (none / one end / both) or switch between a solid and dashed line. Delete removes the selected arrow; deleting a box removes its arrows too, as one undo step.
- **Frames.** Add a labelled, coloured area from the toolbar to group boxes together. Drag a frame by its title bar to move everything inside it; resizing a frame leaves its contents where they are. Frames can be nested inside other frames. Rename a frame inline, pick its colour from its title bar, and collapse it to a title bar only, hiding its boxes (and their arrows) until you expand it again. Deleting a frame keeps its boxes — they just stop belonging to it. Frames always sit behind boxes, and work with snap guides, undo/redo, sync, thumbnails and exports like any other box.
- **Templates.** **Save as template** (in a page's card menu, or in the editor's header) keeps a copy of its layout and boxes: text, lists, tables, stickies, frames, arrows and drawing. **New page** now opens a picker with **Blank** and every template, each shown as a live picture; the new page is a fully independent copy with its own boxes, titled with the template's name. Templates don't appear in the library, search, tag counts or trash.
- **Starter templates and managing them.** Six starters are added the first time you open the app: Meeting notes, Weekly review, Project plan, To-do list, Brainstorm board (stickies in frames) and Daily page. They're ordinary templates: edit or delete them freely (a deleted one doesn't come back). **Templates** in the sidebar lists them as cards; click one to edit it like a page, under an **Editing template** banner, or use its menu to rename, duplicate, delete, make a page from it, or **Use for daily pages**. Deleting a template doesn't change pages already made from it. **Settings** (bottom of the sidebar) chooses which template new daily pages start from.
- **More templates.** Fifteen further starters join the original six (they appear in **Templates** the first time you open an updated app, and removing one is permanent, as before): **Form builder**, **Registration form**, **Feedback survey**, **Mind map**, **Kanban board**, **SWOT analysis**, **Priority matrix**, **Cornell notes**, **Flowchart**, **Habit tracker**, **Budget tracker**, **Study plan**, **Retrospective**, **Trip planner** and **Decision matrix**.
  - **Form builder** has a *Field palette* (short answer, paragraph, multiple choice, dropdown, date, rating), a *Your form* frame to assemble the form in, and a *Form logic* frame with arrows for the flow. Select a palette field, press Ctrl+D, drag the copy into your form and retype its label. Fields are ordinary boxes (a table is the input, a list gives tick boxes), so forms export, sync and print like any other page.
  - If you opened an earlier build of these, the starters you have never edited are replaced once by the redrawn versions (one you changed, renamed or deleted is left alone).
  - **Mind map** is spread across a wide canvas and starts as an **infinite** page, so you can keep adding branches in any direction.
- **Daily tracking and attendance.** In a checklist's hover bar, **Track daily** makes it a daily habit list. The app remembers which items you checked each day, and clears the checks when you open the page on a new day (it never works in the background; the day is closed as soon as you open the list or come back to it). **Attendance** (shown once tracking is on) makes a page called "Attendance: …" with a summary table (days done, days counted, percentage, current and best streak per item) and a **GitHub-style heatmap** (a square per day, a column per week with Monday at the top, up to a year back): the greener a day, the more of the list you did; grey means missed and an outline is today until you've done something. There is one for the whole list, with a summary table beside it (days done, days counted, percentage, current and best streak per item), and one for each item below. A day with nothing checked counts as missed, including days you didn't open the app. The attendance page updates itself as you tick things and whenever you open it; the heatmaps are pictures that are redrawn only when they change, and the rest are ordinary tables, so you can move them, add your own notes beside them, export it, or edit the checklist's items freely (an item added later is only counted from the day you added it). A tracked list has no **Clear done** (its items are what the history is kept for), and copies of a tracked list or a template made from it start with no history. **Stop tracking** forgets the daily record. Tracking is kept in the checklist itself, so it syncs like any page, and older app versions just show the list.
- **Journal.** **Journal** in the sidebar (or **Ctrl+Alt+D** anywhere, or **Open the journal** in the command palette) opens the daily pages as a **book with one page per day**. It shows one page at a time. The page is the day's real page: write, draw and add boxes on it exactly as on any page (it has a cut-down header: undo, redo, outline, history, export and the assistant). **Turn pages** with the arrows, the **[** and **]** keys (when you aren't typing), the **calendar** (days that have a page carry a dot), **Today**, or **Earlier entry / Later entry**, which skip blank days; the page swings in from the spine as it turns (not with *reduce motion* on). **Contents** lists every day that has a page, newest first by month, with the first words *you* wrote (lines that came with the daily template, such as "Focus", are skipped, and an untouched day says "nothing written yet"), and a box to search the whole journal by date or words. Opening the Journal makes **today's** page from the daily template if it doesn't exist yet; another day only gets a page when you press **Start this day** (**Plan this day** for a day to come), so turning through the book leaves nothing behind. The trash button in the page's heading deletes that day's page (it goes to Trash, and today's is not made again for the rest of the session). The **Attendance** button at the top opens the attendance page of a checklist tracked daily (a menu if you track several; a hint if none yet). Attendance pages are kept out of **All pages**, **Groups**, **Tags** and their counts, and their back button returns to the Journal. Titles are by date ("Mon, 19 Oct 2026", from the computer's local date), the template is chosen in **Settings → Journal**, and days are never created in the background. The **Week** button (or **Review my week…** in the command palette) shows what the week, Monday to Sunday, looked like, worked out on this computer from your pages: the first thing written each day, to-dos done and still open on the week's daily pages (a task done later in the week is not "open"), how often each item of a daily habit list was done (today is left out until it is done, and days before an item was added don't count), and the pages you worked on. Nothing is saved until **Create page**, which makes an ordinary page "Week of …" with that laid out in two columns (days and pages as `[[links]]` on the left, tasks and habits on the right). If the AI assistant is on, **Create page and ask AI to reflect** makes the page and hands it to the Chat screen with a request for a short reflection, through the usual "this is what will be sent" step for a cloud or network model.
  - **Daily pages are still ordinary pages** (a page with a date), so they sync, back up and export as before; they are just not listed in **All pages**, **Groups**, **Tags** or their counts, and the **Today** and **Calendar** buttons are gone from the page list. Anything that opens a day's page (the quick switcher, a link, an old address) opens the book at that day instead. New daily pages are no longer filed in a **Daily** group; one an older version made is left as it is (it will show as empty, and can be deleted: nothing in it is lost). If two devices each make the same day before they sync, the older page stays the daily page and the other becomes an ordinary page titled "… (second copy)" (nothing is merged or lost). On some desktops Ctrl+Alt+D is taken by the system (for example KDE's "show desktop"); the Journal entry in the sidebar always works.
- **Damaged data can't blank the app.** Pages that arrive damaged (from another device or version) are repaired when read: boxes missing fields get harmless defaults, entries that can't be boxes are left out, valid data is untouched. If a screen still fails, only that part is replaced by a message with a way out ("Back to the library", or for drawing "Back to the page" and "Erase the drawing") instead of the whole window going blank. A saved drawing with unreadable strokes is cleaned before it is opened.
- **Add-ons (AI assistant, text from pictures).** **Settings → Add-ons** lists optional extras. A switched-off add-on isn't even loaded: it does nothing and makes no network requests. Settings for each appear under its switch once it is on.
  - **AI assistant.** An **Assistant** button in the page header opens a chat drawer beside the page. Choose the provider in Settings → Add-ons: **Ollama** (on this computer by default; "Find models" lists what you have), **Claude** or **ChatGPT** with your own API key. The assistant can be given the page (or only the boxes you've selected, up to about 24,000 characters; a counter shows how much), and offers **Summarize**, **Write a report**, **Make a checklist** and **Improve the wording**. On each answer, **Add to page** puts it on the page as a text box (Markdown becomes headings, lists and bold), **Add as checklist** appears when the answer has `- [ ]` items, and **Copy** copies it. You can tick **Draw a picture instead of answering** to generate a picture from your description with the picture source (shown when the picture source is a local server, or when ChatGPT is the chat provider) and **Add to page** as a picture box. **Stop** ends an answer part-way and keeps what had arrived.
  - **Gemini, Claude and Ollama together.** In **Settings → Add-ons → AI assistant**, **Use** now offers **Gemini (Google)** beside Ollama, Claude and ChatGPT, and the choice applies to the Assistant drawer, the Chat screen, inline "Edit with AI", reports and page edits alike. Cloud models need an **API key** (pasted once, kept in the app's own owner-only file, never in your notes, sync, backups or exports): Gemini at aistudio.google.com/apikey (free tier), Claude at console.anthropic.com. A claude.ai or Gemini app subscription does not include API access, and the apps can't sign in to those accounts. **Pictures** have their own setting, **Draw pictures with**: OpenAI, **Google Gemini** (`gemini-2.5-flash-image` by default, or an `imagen-…` model; image generation often needs billing on the Google key) or a server on your own computer, independent of the chat model, so Ollama can answer chats while Gemini draws. Claude does not draw pictures. The drawer's **Draw a picture instead of answering** names exactly where the description goes, and only what you type is sent. Requests go through the app's Rust side, which only talks to `generativelanguage.googleapis.com` (the model endpoints) for Gemini and keeps the key in a header, never in the address.
  - **The assistant can change the page (you approve every change).** In the Assistant drawer, **Let the assistant suggest changes to this page** (on by default, needs the page shared) shows the model your boxes one by one with labels (b1, b2 …; real ids never leave the app), so it knows what each box says. Ask it to fix, rewrite, add to or remove something ("fix the spelling in my text box", "add a to-do list", "make the table's last column dollars") and it answers with a short note plus a **Suggested changes: not applied yet** card: for each box, what it says **Now** and what it **Becomes**; click a title to jump to the box. **Nothing on the page changes until you press Apply** (or **Discard**). Apply makes all the accepted changes as **one undo step**, and the card then offers **Undo** (Ctrl+Z works too). It can rewrite text boxes and sticky notes, checklists (items you kept keep their identity), code boxes and tables, add a text box, sticky note or checklist, and delete a box. It cannot change pictures, audio, PDFs, cards, frames or the generated attendance table. A suggestion is skipped, with the reason shown, if it names a box it wasn't shown, doesn't fit the box's kind, or the box was edited after the page was sent (it never overwrites what you typed meanwhile). Selecting boxes limits what the assistant sees (and can change) to those. A cloud or network model still shows you the exact message first, including the added instructions. Untick the option and the assistant only reads and answers, as before.
  - **Chat (a screen of its own).** With the add-on on, **Chat** is the first entry in the library sidebar: a full-page conversation that isn't tied to one page, separate from a page's Assistant drawer. It has an empty state with four starters, a message box, the provider and model with the same *On this computer / Another computer / Cloud* badge, and **New chat**. **Add pages** lets you pick up to five of your pages (search by title; each shows as a chip with how many characters it adds, and the limit is shared between them) to ask about; they go along with that one question, in `<page>` tags, and later questions in the conversation can still refer to them. A cloud or network model shows you the exact message, pages included, before it goes, as everywhere else. Answers are shown formatted (headings, lists, bold, code); **Save as a page** turns an answer into a new page named after its first line (with an **Open** button in the confirmation), **Copy** copies it, **Try again** asks the last question again, and **Stop** or Escape ends an answer being written. The conversation is kept while you move around the app (so you can open a page and come back), is separate from the drawer's, and is **never saved**: it is forgotten at **New chat** or when the app is closed. Switching the add-on off while Chat is open returns you to All pages. **Open AI chat** is also in the command palette.
  - **Search or ask (Ctrl+K).** The top of the sidebar has a search box with its shortcut (it says **Search** with the add-on off, **Search or ask** with it on). It, **Ctrl+K** and Ctrl+O all open the quick switcher. With AI on, type a question and the last row is **Ask AI: “…”**: it opens Chat and asks it there (it is last so Enter still opens the best page match).
  - **Ask my notes.** On the Chat screen, **Search my notes** (or the **Ask my notes** starter, or **Ask my notes…** in the command palette) answers a question from *your own pages* with sources. The search runs on this computer: your question is matched against every box's text (BM25-style ranking, a bonus for words in the page title, at most three passages per page and about 6,000 characters in all), and only those few passages go into the message, numbered [1], [2] … with the page's title. The model is told to answer only from them and to cite the numbers; under the answer, each cited note is a button that opens that page and selects that box. Real page and box ids never go to the model. A cloud or network model shows you the exact message first, as for any shared page; a model on this computer is asked straight away. If no passage shares a word with the question, the app answers "I couldn't find anything in your notes" itself and sends nothing at all. Templates, cards and generated attendance pages are not searched. It is off by default and per question: switch it off and the notes stay out of the message.
  - **Edit with AI, and Write with AI (inline).** Modelled on how Notion AI's behaviour is publicly documented (highlight text and ask AI to change it; start a prompt on a blank line; accept, discard or try again), with our own wording and code. In a text box, the **✨ AI** button in the formatting bar opens a small card for the selected text (or the whole box when nothing is selected). Type an instruction ("Tell AI what to do with this text…") or pick one of six actions: **Improve writing**, **Fix spelling and grammar**, **Make shorter**, **Make longer**, **Summarize**, **Continue writing**. **More…** adds **Simplify**, **Explain this**, **Find action items**, a **Change tone** row (professional, casual, friendly, confident, straightforward) and a **Translate to** row (11 languages). The answer streams into the card; then **Replace selection** (or **Replace text**) / **Insert below** (the main button depends on the action: rewrites replace, summaries and continuations go below), **Try again**, **Discard**, and a box to refine it ("Tell AI what to do next…"). Replace is refused, with a message, if the text was edited while the answer was being written. **Pressing space in an empty text box** (it says "Type, or press space for AI") or **Write with AI…** in the command palette opens a prompt on the page: ask for anything, or pick **Continue writing this page**, **Brainstorm ideas**, **Write an outline**, **Find action items** or **Summarize this page** (each shares the page as context, with its size shown, and you can untick it). The result goes into the empty box, or into a new text box; action items can go in as a **checklist**. Only the selected text (or, for Write, the page if you leave it ticked) is sent, and a cloud or network provider shows you the exact message first, as in the Assistant. The Assistant panel also gained **Find action items**, **Continue writing** and **Brainstorm ideas**, and **Try again** on the last answer (also after an error).
  - **Pictures, with open-source models on your own computer.** Under **Pictures** in the add-on's settings, **Draw pictures with** chooses who draws, independently of the chat provider: **OpenAI (cloud)**, a **Stable Diffusion WebUI server** (AUTOMATIC1111, Forge, SD.Next: start it with `--api`; default address `http://127.0.0.1:7860`), or an **OpenAI-compatible image server** (such as LocalAI; default `http://localhost:8080`, which serves `/v1/images/generations`). Which open-source model you get (Stable Diffusion 1.5 or XL, FLUX.1 schnell and so on) depends on what you've installed on that server; leave **Model** empty to use whatever it has loaded, or name one (**Check connection** lists what the server offers). You can also set the picture size (512, 768 or 1024) and, for the WebUI, the steps. A local server needs no key and your description never leaves your computer (a server on another computer gets it over your network; the settings say which). Servers may answer with PNG, JPEG or WebP; the app detects which. Model licences differ (for example FLUX.1 schnell is Apache-2.0, other models limit commercial use): check each one. ## 2. Phone setup (Android)

Building for Android needs Android Studio, which brings the Android SDK, the NDK and Java.

1. **Install Android Studio:** `sudo snap install android-studio --classic`, then open it once and finish the setup wizard.
2. In Android Studio, open **More Actions → SDK Manager**:
   - On **SDK Platforms**, tick the newest Android version.
   - On **SDK Tools**, tick **Android SDK Build-Tools**, **NDK (Side by side)**, **Android SDK Command-line Tools** and **Android SDK Platform-Tools**.
   - Click **Apply**.
3. **Tell the build tools where everything is.** Add these lines to the end of `~/.bashrc`, then open a new terminal:

   ```bash
   export JAVA_HOME=/snap/android-studio/current/jbr
   export ANDROID_HOME="$HOME/Android/Sdk"
   export NDK_HOME="$ANDROID_HOME/ndk/$(ls -1 "$ANDROID_HOME/ndk" | sort -V | tail -1)"
   ```

4. **Add Rust's Android targets:**

   ```bash
   rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
   ```

5. **Prepare your phone:**
   1. Go to **Settings → About phone** and tap **Build number** seven times. This turns on Developer options.
   2. In **Developer options**, turn on **USB debugging**.
   3. Plug the phone in and accept the prompt on its screen.
6. **Create the Android project** (once): `npm run android:init`
7. **Run it on the phone:** `npm run android:dev`. The phone must be on the same Wi-Fi as the laptop, because it loads the app from the laptop while you develop.

**The development app on your phone, kept in step with the project.** Once the setup above is done, one command puts the current code on the phone:

```bash
npm run phone          # build the current code, install it over the old copy, open it
npm run phone:live     # live reload: edits show on the phone as you save (same Wi-Fi as the laptop)
npm run phone:build    # only build the APK
scripts/phone.sh connect 192.168.1.20:37000   # use the phone over Wi-Fi instead of a cable (Developer options → Wireless debugging)
```

`npm run phone` installs with `adb install -r`, which **keeps the app's data**: the notes on the phone and its sync pairing survive every update, and the app upgrades its own database the first time it opens. Run it again whenever the project changes. With several phones plugged in, set `ANDROID_SERIAL=<serial>` (`scripts/phone.sh devices` lists them). If the install says the copy on the phone was signed with a different key, sync first, uninstall the app on the phone (its notes come back from the laptop on the next sync) and run the command again. Uninstalling wipes the phone's copy; the laptop keeps its own.

Then pair it once (section 3 below). From then on whatever you write on either device reaches the other, and an update to the project reaches the phone with `npm run phone`. Keep the laptop and phone on the same version: a phone older than the laptop is refused by sync until it is updated.

**To install the app permanently without the laptop script,** run `npm run android:apk`. The APK appears in `src-tauri/gen/android/app/build/outputs/apk/`. Copy it to the phone and open it, or run `adb install <file>.apk`.

This is a debug build, which is fine for your own phone. A Play Store release needs a signing key; see https://v2.tauri.app/distribute/sign/android/.

Gradle (Android's build tool) is memory-hungry. Close the browser and other big apps during the first Android build.

## 3. Sync between phone and laptop

1. **On the laptop:** open Canvas Notes, click **Sync**, and turn on **Let my phone sync with this laptop**. It shows the laptop's address and a pairing code.
2. **On the phone:** open Canvas Notes, tap **Sync**, enter the address and the code, and tap **Connect**.

After that the phone syncs on its own:
- when the app opens or comes back to the front
- every two minutes while it's open
- about 20 seconds after you edit

This works whenever both devices are on the same Wi-Fi and the app is open on the laptop. **Sync now** forces it immediately.

**How it works.** The laptop runs a small service on port 47821, and the phone talks to it directly. Every message is encrypted (ChaCha20-Poly1305) with a key made from the pairing code. The code itself never travels over the network, so other devices on the Wi-Fi can't read or fake sync traffic. **New pairing code** on the laptop locks out phones using the old code.

**What syncs:** pages, groups and subgroups, tags and images, plus deletions. Update the app on both devices together: an older phone app treats subgroups as top-level groups, and if you edit one there, its nesting is lost.
- A page edited on only one side between syncs takes that side's version.
- A page edited on both sides is kept twice: the laptop's version under the original name, and the phone's as "(conflicted copy)".
- An edit beats a deletion: if one side deleted a page the other side was still editing, the page stays.

**If the phone can't connect:**
- Check both devices are on the same network, not a guest network.
- If Ubuntu's firewall is on, run `sudo ufw allow 47821/tcp`.
- If the laptop's address changes every few days, reserve a fixed IP for it in your router's settings (often called "DHCP reservation").
- The phone's and laptop's clocks must be within 5 minutes of each other. Automatic time on both handles this.

### How data is stored

Each page is one row; its `blocks` column is JSON:

```json
{ "id": "…", "type": "text", "x": 136, "y": 64, "w": 432, "h": 40, "z": 1, "html": "<p>…</p>" }
```

A page's `arrows` column is likewise JSON: each entry references two block ids (`from`/`to`)
rather than storing its own position, so its route is always recomputed from the current
blocks. Missing from a record written by an older app version, it's just treated as `[]`.

A frame is just another entry in `blocks` (`"type": "frame"`, with its own `title`, `color`
and `collapsed`), and a block names the frame it's inside via `frameId` — so frames need no
schema changes, migration, or sync-engine code; undo/redo, sync and storage all already work
generically off `blocks`.

Pages and groups also carry three sync fields:
- `etag`: changes on every save.
- `synced`: the version both devices last agreed on.
- `deleted`: deleted rows are kept as markers so the deletion can sync.

To add a new kind of box:
1. Add its type in `types.ts`.
2. Add a body component in `components/blocks/`.
3. Render it in `BlockFrame.tsx`.
4. Add a toolbar button in `Editor.tsx`.

Undo, saving, sync and thumbnails work for it without changes.

Schema changes go in `MIGRATIONS` in `src/storage/tauri.ts`. Each entry runs once.
